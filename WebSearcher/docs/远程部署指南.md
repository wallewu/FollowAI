## 🤔 为什么需要远程部署？

### 本地模式（stdio）的限制

- ✅ 简单易用，适合个人使用
- ✅ 无需网络配置
- ❌ 客户端和服务器必须在同一台机器上
- ❌ 无法共享服务给多个用户
- ❌ 难以集中管理和监控

### 远程模式（HTTP/SSE）的优势

- ✅ 客户端和服务器可以分离部署
- ✅ 多个客户端可以共享同一个服务器
- ✅ 便于集中管理API密钥和配置
- ✅ 可以部署到云服务器
- ✅ 支持负载均衡和高可用
- ✅ 便于监控和日志收集

## 🚀 快速开始

### 1. 安装依赖

```bash
cd WebSearcher
pip install -e .
# 或
pip install mcp httpx python-dotenv aiohttp
```

### 2. 配置环境变量

创建`.env`文件：

```env
# 搜索引擎配置
SEARCH_ENGINE=serpapi
SERPAPI_KEY=your_serpapi_key_here

# 服务器配置
MAX_RESULTS=10
REQUEST_TIMEOUT=30
LOG_LEVEL=INFO
DEBUG_MODE=false
```

### 3. 启动HTTP服务器

```bash
# 默认配置（监听0.0.0.0:8000）
python -m src.server --mode http

# 自定义主机和端口
python -m src.server --mode http --host 0.0.0.0 --port 8080

# 仅监听本地（更安全）
python -m src.server --mode http --host 127.0.0.1 --port 8000
```

### 4. 验证服务器运行

```bash
# 健康检查
curl http://localhost:8000/health

# 应该返回：
# {"status": "healthy", "service": "websearcher-mcp"}
```

### 5. 配置MCP客户端

在Claude Desktop配置文件中：

```json
{
  "mcpServers": {
    "websearcher-remote": {
      "url": "http://your-server-ip:8000",
      "transport": "http"
    }
  }
}
```

**注意**：目前Claude Desktop主要支持stdio传输，HTTP传输支持可能有限。建议使用自定义MCP客户端或等待官方支持。

## ⚙️ 详细配置

### 命令行参数

```bash
python -m src.server --help
```

**可用参数**：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--mode` | 传输模式：`stdio`或`http` | `stdio` |
| `--host` | HTTP模式下绑定的主机地址 | `0.0.0.0` |
| `--port` | HTTP模式下监听的端口 | `8000` |

### HTTP端点

服务器提供以下HTTP端点：

#### 1. 健康检查

```
GET /health
```

**响应**：
```json
{
  "status": "healthy",
  "service": "websearcher-mcp"
}
```

#### 2. Server-Sent Events（SSE）

```
GET /sse
```

用于建立持久连接，接收服务器推送的事件。

**响应头**：
```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

#### 3. 消息处理

```
POST /message
Content-Type: application/json
```

**请求体**（JSON-RPC 2.0格式）：
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {}
}
```

**响应**：
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [...]
  }
}
```

### 环境变量

所有本地模式的环境变量在远程模式下同样适用。参见[配置参数说明.md](配置参数说明.md)。

## 🌐 部署方案

### 方案1：本地网络部署

适用于：团队内部使用，局域网环境

```bash
# 在服务器上启动
python -m src.server --mode http --host 0.0.0.0 --port 8000

# 客户端访问
# http://192.168.1.100:8000
```

**优点**：
- 简单快速
- 无需公网IP
- 低延迟

**缺点**：
- 仅限局域网访问
- 需要防火墙配置

### 方案2：云服务器部署

适用于：公网访问，多用户共享

#### 2.1 使用systemd服务

创建服务文件`/etc/systemd/system/websearcher.service`：

```ini
[Unit]
Description=WebSearcher MCP Server
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/websearcher
Environment="PATH=/opt/websearcher/venv/bin"
EnvironmentFile=/opt/websearcher/.env
ExecStart=/opt/websearcher/venv/bin/python -m src.server --mode http --host 0.0.0.0 --port 8000
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable websearcher
sudo systemctl start websearcher
sudo systemctl status websearcher
```

#### 2.2 使用Docker

创建`Dockerfile`：

```dockerfile
FROM python:3.10-slim

WORKDIR /app

# 安装依赖
COPY pyproject.toml .
RUN pip install -e .

# 复制源代码
COPY src/ ./src/

# 暴露端口
EXPOSE 8000

# 启动命令
CMD ["python", "-m", "src.server", "--mode", "http", "--host", "0.0.0.0", "--port", "8000"]
```

构建和运行：

```bash
# 构建镜像
docker build -t websearcher-mcp .

# 运行容器
docker run -d \
  --name websearcher \
  -p 8000:8000 \
  -e SEARCH_ENGINE=serpapi \
  -e SERPAPI_KEY=your_key_here \
  --restart unless-stopped \
  websearcher-mcp

# 查看日志
docker logs -f websearcher
```

#### 2.3 使用Nginx反向代理

配置Nginx（`/etc/nginx/sites-available/websearcher`）：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # SSE特殊配置
    location /sse {
        proxy_pass http://127.0.0.1:8000/sse;
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding off;
    }
}
```

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/websearcher /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 方案3：使用云平台

#### 3.1 AWS EC2

```bash
# 1. 启动EC2实例（Ubuntu 22.04）
# 2. 配置安全组，开放8000端口
# 3. SSH连接到实例
ssh -i your-key.pem ubuntu@your-ec2-ip

# 4. 安装依赖
sudo apt update
sudo apt install python3-pip python3-venv
git clone your-repo
cd WebSearcher
python3 -m venv venv
source venv/bin/activate
pip install -e .

# 5. 配置环境变量
cp .env.example .env
nano .env  # 编辑配置

# 6. 启动服务
python -m src.server --mode http
```

#### 3.2 Google Cloud Run

创建`cloudbuild.yaml`：

```yaml
steps:
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/websearcher', '.']
  - name: 'gcr.io/cloud-builders/docker'
    args: ['push', 'gcr.io/$PROJECT_ID/websearcher']
  - name: 'gcr.io/cloud-builders/gcloud'
    args:
      - 'run'
      - 'deploy'
      - 'websearcher'
      - '--image=gcr.io/$PROJECT_ID/websearcher'
      - '--platform=managed'
      - '--region=us-central1'
      - '--allow-unauthenticated'
```

部署：

```bash
gcloud builds submit --config cloudbuild.yaml
```

#### 3.3 Heroku

创建`Procfile`：

```
web: python -m src.server --mode http --host 0.0.0.0 --port $PORT
```

部署：

```bash
heroku create your-app-name
heroku config:set SEARCH_ENGINE=serpapi
heroku config:set SERPAPI_KEY=your_key_here
git push heroku main
```

## 🔒 安全考虑

### 1. API密钥保护

**不要**：
- ❌ 在代码中硬编码API密钥
- ❌ 将`.env`文件提交到版本控制
- ❌ 在日志中输出API密钥

**应该**：
- ✅ 使用环境变量或密钥管理服务
- ✅ 在生产环境禁用DEBUG_MODE
- ✅ 定期轮换API密钥

### 2. 网络安全

```bash
# 使用防火墙限制访问
sudo ufw allow from 192.168.1.0/24 to any port 8000

# 或使用iptables
sudo iptables -A INPUT -p tcp -s 192.168.1.0/24 --dport 8000 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 8000 -j DROP
```

### 3. HTTPS加密

**强烈建议**在生产环境使用HTTPS：

```bash
# 使用Let's Encrypt获取免费SSL证书
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### 4. 认证和授权

当前版本不包含认证机制。在生产环境中，建议：

- 使用Nginx添加基本认证
- 使用API密钥验证
- 使用OAuth 2.0
- 使用VPN限制访问

**Nginx基本认证示例**：

```bash
# 创建密码文件
sudo htpasswd -c /etc/nginx/.htpasswd username

# 在Nginx配置中添加
location / {
    auth_basic "Restricted Access";
    auth_basic_user_file /etc/nginx/.htpasswd;
    proxy_pass http://127.0.0.1:8000;
}
```

### 5. 速率限制

防止滥用，建议添加速率限制：

**Nginx配置**：

```nginx
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

location /message {
    limit_req zone=api_limit burst=20 nodelay;
    proxy_pass http://127.0.0.1:8000;
}
```

## 🐛 故障排查

### 服务器无法启动

**检查端口占用**：
```bash
sudo lsof -i :8000
# 或
sudo netstat -tulpn | grep 8000
```

**检查防火墙**：
```bash
sudo ufw status
sudo iptables -L
```

### 无法从客户端连接

**测试网络连通性**：
```bash
# 从客户端机器
curl http://server-ip:8000/health
telnet server-ip 8000
```

**检查服务器日志**：
```bash
# systemd服务
sudo journalctl -u websearcher -f

# Docker容器
docker logs -f websearcher
```

### API请求失败

**启用调试模式**：
```env
DEBUG_MODE=true
LOG_LEVEL=DEBUG
```

**检查API密钥**：
```bash
# 测试SerpAPI密钥
curl "https://serpapi.com/search?q=test&api_key=YOUR_KEY"
```

### 性能问题

**监控资源使用**：
```bash
# CPU和内存
top
htop

# 网络连接
ss -s
netstat -an | grep 8000 | wc -l
```

**优化建议**：
- 增加REQUEST_TIMEOUT
- 使用负载均衡
- 启用结果缓存
- 限制并发连接数

## 📊 监控和日志

### 日志收集

**使用journald**：
```bash
sudo journalctl -u websearcher -f --since "1 hour ago"
```

**使用Docker**：
```bash
docker logs --tail 100 -f websearcher
```

### 健康检查脚本

创建`health_check.sh`：

```bash
#!/bin/bash
ENDPOINT="http://localhost:8000/health"
RESPONSE=$(curl -s -o /dev/null -w "%{http_code}" $ENDPOINT)

if [ $RESPONSE -eq 200 ]; then
    echo "✅ Service is healthy"
    exit 0
else
    echo "❌ Service is unhealthy (HTTP $RESPONSE)"
    exit 1
fi
```

### 监控工具集成

- **Prometheus**: 添加metrics端点
- **Grafana**: 可视化监控数据
- **ELK Stack**: 集中日志管理
- **Datadog**: 全方位监控
